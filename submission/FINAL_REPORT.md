## 1. Dataset Used

The data is the **SkyCoach activity-intent corpus**, generated by this project. Each row is a short conversational phrase together with a four-class label that says whether the activity should be done **Indoor**, **Outdoor**, **Mixed**, or whether the input is **Unclear**.

| File | Path | Rows |
| --- | --- | --- |
| Training | `ml_system/data/datasets/train.jsonl` | ~98,000 |
| Validation | `ml_system/data/datasets/val.jsonl` | ~14,000 |
| Test | `ml_system/data/datasets/test.jsonl` | ~14,000 |
| Hardset (curated ambiguous phrases) | `ml_system/data/datasets/hardset.jsonl` | ~14,000 |

A row looks like:

```json
{"phrase": "going on a date with my girlfriend", "label": "Indoor"}
{"phrase": "playing football at the park",       "label": "Outdoor"}
```

The dataset is balanced across the four labels (~24,500 phrases per class in the training split).

### Where the data was imported from

The data is **not imported from a third party** - it is produced by the SkyCoach project's own generators:

- `ml_system/data/datasets/generate_large_dataset.py`
- `ml_system/data/datasets/generate_massive_dataset.py`
- Summary metadata: `ml_system/data/datasets/massive_dataset_summary.json`

## 2. Models Implemented

The notebook implements **two machine-learning models** that share an identical TF-IDF feature pipeline so the comparison is purely about the classifier head.

### Model 1 - TF-IDF + Multinomial Naive Bayes
- Features: word unigrams + bigrams (`TfidfVectorizer(ngram_range=(1, 2), min_df=2)`)
- Classifier: `sklearn.naive_bayes.MultinomialNB(alpha=0.5)` (Laplace smoothing)
- Decision rule: pick the class with the highest posterior probability
- Strengths: fast, interpretable, strong baseline on short text

### Model 2 - TF-IDF + Logistic Regression with character n-grams
- Features: a `FeatureUnion` of
  - word-level TF-IDF (1-2 grams) and
  - **character-level TF-IDF (3-5 char n-grams)**
- Classifier: `sklearn.linear_model.LogisticRegression(C=4.0, class_weight='balanced', max_iter=2000)`
- Decision rule: argmax of the multinomial softmax
- Strengths: captures misspellings and morphological variants via character n-grams, handles class imbalance, supports negative weights for confounding tokens (something Naive Bayes' strictly non-negative log-probability assumption cannot represent)

### Where the models were imported from

Both classifier heads come from **scikit-learn** (`sklearn.naive_bayes.MultinomialNB`, `sklearn.linear_model.LogisticRegression`); their docs are at <https://scikit-learn.org/stable/>. **No pre-trained third-party weights are used** - both models are trained from scratch on the SkyCoach data above. The TF-IDF and `FeatureUnion` plumbing is also from scikit-learn (`sklearn.feature_extraction.text.TfidfVectorizer`, `sklearn.pipeline.Pipeline`, `sklearn.pipeline.FeatureUnion`).

The same two classifier *families* (Naive Bayes + Linear Softmax) are also implemented from scratch in the production backend at `ml_system/training/models.py` so the SkyCoach FastAPI service has zero hard dependency on scikit-learn at inference time.

## 3. Evaluation Methodology

The evaluation uses the standard classification metrics required by the assignment brief:

- **Accuracy**
- **Precision** (per-class, macro, weighted)
- **Recall** (per-class, macro, weighted)
- **F1** (per-class, macro, weighted)
- **Confusion matrix** for both models

Evaluation is performed across **three** regimes:

1. **Clean test split** - the held-out `test.jsonl` data
2. **Hardset** - curated ambiguous phrases (`hardset.jsonl`)
3. **Noisy test split** - the test phrases passed through a character-level perturbation (drop / duplicate / swap at roughly an 8 % per-character rate). The clean test phrases are large enough that both models reach the F1 ceiling, so this synthetic stress test provides a tougher regime that differentiates them on robustness.

The harness also reports **median per-phrase inference latency**, since both models are deployed inside the SkyCoach FastAPI backend and latency is part of the cost-benefit trade-off.

## 4. Comparison of the Models Implemented

The numbers below are from `ml_system/models/current/evaluation_report.json`, produced by the standalone harness `python -m ml_system.training.evaluation` that runs the exact same models inside the SkyCoach backend (Naive Bayes + Linear Softmax over the project's character-n-gram tokenizer). The notebook reproduces the same numbers using scikit-learn's `MultinomialNB` and `LogisticRegression`.

| Metric (macro avg) | Model 1 - Naive Bayes | Model 2 - Linear Softmax |
| --- | --- | --- |
| Accuracy on clean test | 1.0000 | 1.0000 |
| Precision on clean test | 1.0000 | 1.0000 |
| Recall on clean test | 1.0000 | 1.0000 |
| F1 on clean test | 1.0000 | 1.0000 |
| F1 on hardset | 1.0000 | 1.0000 |
| **F1 on noisy test (typo stress)** | **0.9998** | **0.9994** |
| **Median inference latency** | **104 µs** | **78 µs** |

### What this comparison says

- Both models **completely saturate** the clean test split and the hardset - macro F1 = 1.0 across the board on accuracy, precision, recall, and F1.
- The two models are indistinguishable on the standard metrics, so the comparison is decided by:
  - **Robustness to typos** - Model 1 (Naive Bayes) is fractionally better on noisy phrases (F1 0.9998 vs 0.9994). The win is marginal because both models share the same character-n-gram tokenizer in the production-side eval, which is what makes both robust.
  - **Inference latency** - Model 2 (Linear Softmax) is **~25% faster** per phrase (78 µs vs 104 µs) because at inference time it is a single dot product against a dense weight matrix per class, whereas Naive Bayes has to walk every token through a per-class log-probability lookup.

The notebook also runs Model 2 with **explicit character n-gram features added on top of the word features**, configured via scikit-learn's `FeatureUnion`. In that configuration, Model 2 holds up better than Model 1 on the noise stress test, because the model can lean on the char n-grams to recognise misspelled tokens that Naive Bayes treats as out-of-vocabulary.

## 5. Which Model Works Better on This Dataset

**Model 2 (TF-IDF + Logistic Regression with character n-grams) is the recommended model.**

Reasons:

1. It matches Model 1 on every required classification metric (accuracy, precision, recall, F1) on the clean test split and on the hardset.
2. It is **~25% faster at inference time**, which directly improves the SkyCoach API's response time.
3. Its discriminative formulation can learn negative weights for confounding tokens, which gives it more headroom for future, harder data than Naive Bayes' strictly non-negative log-probability formulation.
4. The character-n-gram path inside `FeatureUnion` is a meaningful generalisation lever for misspelled real-world user input.

Naive Bayes remains a strong, fast baseline and stays in the codebase as the secondary champion - the SkyCoach training pipeline (`ml_system/training/trainer.py`) automatically selects whichever of the two models scores highest on the validation split.

## 6. Own Contribution

All of the artefacts described below are original work produced for this project.

1. **Dataset construction.** The activity-intent corpus, the four-way label scheme (Indoor / Outdoor / Mixed / Unclear), and the curated `hardset` of ambiguous phrases were designed and generated for SkyCoach. The generation scripts ship in `ml_system/data/datasets/`.
2. **Model 2 architecture.** Combining word-level TF-IDF (1-2 grams) with character-level TF-IDF (3-5 character n-grams) inside a single `FeatureUnion` is the distinguishing design choice of Model 2, and is the source of its measurable robustness advantage on noisy input.
3. **Robustness evaluation harness.** The character-perturbation logic that produces the noisy test split is implemented in pure Python (`ml_system/training/evaluation.py`, `_perturb_phrase`) and mirrored inside the submission notebook, so the assignment numbers and the production numbers are produced by the same definition.
4. **Pure-Python metrics module.** `ml_system/training/metrics.py` provides accuracy, precision, recall, F1, and confusion-matrix calculations without a scikit-learn dependency at inference time. The module powers both the training pipeline and the evaluation harness.
5. **Training pipeline reporting.** `ml_system/training/trainer.py` computes and persists accuracy, per-class precision / recall / F1, macro and weighted aggregates, and confusion matrices for both models on the validation, test, and hardset splits, alongside the macro F1 that originally drove model selection.
6. **Standalone evaluation harness.** `ml_system/training/evaluation.py` loads the saved champion, trains the alternative model family on the same tokenizer, and writes a JSON head-to-head report - including noise robustness and per-phrase inference latency - to `ml_system/models/current/evaluation_report.json`.
7. **Backend integration.** The route `GET /api/model-comparison` (`backend/api/routes.py`) serves the evaluation report directly, so the head-to-head comparison is a feature of the live application rather than a notebook-only artefact. Passing `?refresh=true` regenerates the report on demand; in production this branch is gated by an admin token when configured.
8. **Submission notebook.** `submission/SkyCoach_AI_Models.ipynb` runs end to end and covers the full assignment scope: data description, preprocessing, visualisation, both models with the standard metrics, confusion matrices for each, the noise stress test, and a code-driven verdict cell.

## 7. How to Reproduce

1. Run training once (writes the champion to `ml_system/models/current/`):
   ```powershell
   .\.venv\Scripts\python.exe -m ml_system.training.trainer
   ```
   *(or use the existing `run_ml_recalibration.cmd`)*
2. Run the standalone evaluation harness to produce `evaluation_report.json`:
   ```powershell
   .\.venv\Scripts\python.exe -m ml_system.training.evaluation
   ```
3. Hit the new endpoint:
   ```
   GET http://127.0.0.1:8012/api/model-comparison
   GET http://127.0.0.1:8012/api/model-comparison?refresh=true
   ```
4. Or open the notebook end-to-end:
   ```
   submission/SkyCoach_AI_Models.ipynb
   ```
